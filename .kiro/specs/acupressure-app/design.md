# Design — застосунок-довідник точок надавлювання

Статус: **чернетка, очікує погодження**. Етап SDD 2 з 3. Реалізує [requirements.md](requirements.md).

## 1. Дизайн-система

### Рішення: Material 3 як єдина система + платформні адаптації поведінки

Одна візуальна мова на iOS, Android і вебі; платформа впливає на **поведінку**, а не на вигляд компонентів.

| Варіант | Плюси | Мінуси | Вердикт |
|---|---|---|---|
| **Material 3 + адаптації** | Рідна для Flutter, усі потрібні компоненти готові (`NavigationBar`/`NavigationRail`, `SearchAnchor`, `Chip`, `Card`), найкраща доступність і динамічний шрифт, один набір екранів для вебу | На iOS виглядає «не зовсім по-епплівськи» | **Обрано** |
| Material на Android + Cupertino на iOS | Максимально рідний вигляд на кожній платформі | Два набори екранів і тестів; у Cupertino немає чипів, карток, пошуку з підказками, бічної панелі для вебу — довелося б дописувати | Відхилено: подвійна ціна без користі для довідника |
| Власна система з нуля | Унікальний вигляд | Найдорожче, доступність і темна тема вручну | Відхилено |

Для довідника з текстом і малюнками цінність — у читабельності та передбачуваній навігації, а не в нативних контролах.
Material 3 дає це найдешевше, а веб-версія пізніше отримає той самий код.

### Платформні адаптації (що відрізняється на iOS)

- Перехід між екранами і жест «назад» від краю — `CupertinoPageTransitionsBuilder`.
- Фізика прокрутки з відскоком, великий заголовок, що згортається (`SliverAppBar.large`).
- Системний шрифт: SF Pro на iOS, Roboto на Android (не вшиваємо власний шрифт).
- Іконка «назад» — шеврон, «поширити» — платформна.
- Діалоги підтвердження — `AlertDialog.adaptive`, перемикачі — `Switch.adaptive`.
- Тактильний відгук на додавання в обране.

### Токени

**Колір.** `ColorScheme.fromSeed` від одного кольору, світла й темна схеми.
Seed — приглушений зелено-бірюзовий `#2F6F62`: спокійний, «оздоровчий», не конфліктує з теплим жовтуватим папером сканів.
Динамічний колір Android (Material You) вимкнено — щоб вигляд збігався на всіх платформах.

| Роль | Використання |
|---|---|
| `primary` | активна вкладка, кнопка «в обране» (активна), посилання-коди в тексті |
| `secondaryContainer` | бейдж коду точки |
| `tertiaryContainer` | позначка «соматична» |
| `surfaceContainerLow` | картки, рядки списків |
| `surfaceContainerHighest` | поле пошуку |
| Фіксований `#F3E6C8` (папір) | підкладка під малюнками в обох темах — скани не інвертуємо (R7.4) |
| Фіксований бурштиновий контейнер | блок «рукописні нотатки» (R6.6) |

**Типографіка** — стандартна шкала M3:
`headlineSmall` заголовок екрана · `titleLarge` код точки · `titleMedium` заголовок точки · `bodyLarge` опис (висота рядка 1.5) ·
`labelLarge` чипи і вкладки · `bodySmall` підписи малюнків. Коди точок — моноширинні цифри (`FontFeature.tabularFigures`).

**Форма і відступи.** Радіуси: 12 (картки), 28 (поле пошуку), 8 (чипи). Сітка 4 dp; поля екрана 16 dp; між картками 12 dp.

**Компонент «бейдж коду».** Прямокутник із заокругленням, `secondaryContainer`, ширина за вмістом, мін. 44 dp.
Єдиний на весь застосунок — код точки скрізь виглядає однаково, і око вчиться його шукати.

## 2. Інформаційна архітектура

```
Головна ──────────────── пошук · останні запити · нещодавні · сегменти · словник · налаштування
Тіло ─── Сегмент ─── Точка ─── Малюнок на весь екран
Симптоми ─── Симптом (або Група ─── Симптом) ─── Точка
Збережене ─── Обране | Історія ─── Точка / Сегмент / Симптом
Пошук (поверх будь-якої вкладки) ─── Точка / Симптом / термін Словника
Словник · Налаштування · Застереження (з Головної)
```

Маршрути (`go_router`, придатні як URL для вебу). Корені вкладок: `/`, `/body`, `/symptoms`, `/saved`.

Спільні екрани (точка, сегмент, згодом симптом, малюнок, пошук) мають копію маршруту в **кожній** вкладці,
тому відкриваються в стеку тієї вкладки, з якої прийшли: нижня панель лишається видимою, «назад» веде туди,
звідки прийшли. Префікс — корінь вкладки; для Головної префікса немає, тож її адреси канонічні.

| Шлях (у вкладці Головна) | У вкладці «Тіло» | Екран | Стан |
|---|---|---|---|
| `/` | `/body` | корінь вкладки | є |
| `/point/:code` | `/body/point/:code` | Точка (`/point/12M`, `/point/49-half`) | є |
| `/segment/:id` | `/body/segment/:id` | Сегмент | є |
| `/point/:code/image/:id` | `/body/point/:code/image/:id` | Малюнок точки на весь екран (поверх нижньої панелі) | є |
| `/segment/:id/image/:id` | `/body/segment/:id/image/:id` | Зведена схема сегмента на весь екран | є |
| `/symptom/:id` | `/body/symptom/:id` | Симптом | є |
| `/symptom-group/:id` | `/body/symptom-group/:id` | Група симптомів (Глаза, Голова, Сердце, Боль) | є |
| `/glossary` | `/body/glossary` | Словник | є |
| `/search?q=` | `/body/search?q=` | Пошук | є |
| `/settings` · `/about` | `/body/settings` · `/body/about` | Налаштування · Про джерело і застереження | є |

Перехід до спільного екрана — `context.openPoint(code)` / `context.openSegment(id)` (`core/router/app_tab.dart`):
шлях будується від поточної вкладки й відкривається через `push`. Невідома адреса, код чи сегмент → екран «Не знайдено».

### 3.6 Збережене
Два сегменти вгорі: **Обране** (список точок) і **Історія** (за днями; тип запису позначено іконкою: точка, сегмент, симптом, термін). Дія «Очистити» — в меню верхньої панелі.

### 3.7 Адаптивність (для вебу і планшетів)

| Ширина | Навігація | Макет |
|---|---|---|
| < 600 dp | нижня панель | одна колонка |
| 600–839 dp | нижня панель | сітка сегментів у 3 колонки, ширші поля |
| ≥ 840 dp | бічна панель (`NavigationRail`) | список + деталь поруч (сегмент ліворуч, точка праворуч), вміст до 1200 dp |

У MVP реалізується лише перший рядок, але екрани будуються з `LayoutBuilder` і без жорстких розмірів, щоб два інші додались без переписування.

## 4. Архітектура

- **Стан:** Riverpod (провайдери + `AsyncNotifier`), без кодогенерації в MVP.
- **Навігація:** `go_router` зі `StatefulShellRoute.indexedStack` — окремий стек на вкладку (R1.3).
- **Збереження:** `shared_preferences` для історії, обраного, теми (кілька невеликих JSON-списків; БД не потрібна).
- **Малюнки:** `Image.asset` + `InteractiveViewer` для масштабування.
- **Локалізація:** `flutter_localizations` + ARB (`uk` — основна).

```
app/
  lib/
    main.dart, app.dart            тема, роутер
    core/        theme/, router/, widgets/ (CodeBadge, PaperImage, SectionHeader, EmptyState)
    data/        models/, content_repository.dart, search_index.dart, user_store.dart
    features/
      home/  search/  body/  point/  symptoms/  glossary/  saved/  settings/
    l10n/
  assets/
    content.json                   згенеровано з tools/data
    images/<segment>/*.jpg         скопійовано з atoms/
  test/
```
Залежності між шарами: `features → data → models`; `core` не знає про `features`.

## 5. Дані

### 5.1 Конвеєр

`tools/build_atoms.py` доповнюється експортом `app/assets/content.json` і копіюванням малюнків.
Одне джерело правди — `tools/data/*.txt`; і `atoms/`, і застосунок збираються з нього (R12.8).
Малюнки обмежені 1200 px по довшій стороні; разом із `content.json` (310 КБ) ресурси займають 7 МБ.

### 5.2 Модель

```
Segment   { id, title, sourceTitle, sourcePages, overviewFigureIds[], pointCodes[] }
Point     { code, segmentId, title, somatic, sourcePage, order,
            sections[ { headings[], paragraphs[] } ],   // сторони ліва/права = заголовки секцій
            notes[], transcriptionNotes[],
            figureIds[], relatedCodes[], symptomIds[] }
Figure    { id, asset, kind: overview|detail, caption, sourcePage, segmentId, pointCodes[], width, height }
SymptomGroup { id, title }
Symptom   { id, term, group?, handwritten,
            refs[ { alternative,                         // «или» відносно попереднього
                    parts[ { kind: point|unknown|text,   // кілька parts = натискати разом («+»)
                             codes[], pair, side?: left|right|both, qualifier?, label? } ] } ],
            sourceLines[] }                              // рядки як надруковано
GlossaryTerm { term, definition }
Meta      { legend[], somaticCodes[], unresolvedCodes[], intro { sections[], figureIds[] }, source }
```
Текст абзаців зберігається з розміткою посилань (`[[12M]]` або `[[S1|S1 правая]]`), яку рендерить один віджет `RichContentText`.

Користувацькі дані (`user_store`):
```
searchHistory : [ { query, at } ]            ≤ 20
viewHistory   : [ { type, id, at } ]         ≤ 50, type ∈ point|segment|symptom|term
favorites     : [ { code, at } ]
themeMode     : system | light | dark
disclaimerAccepted : bool           // застереження першого запуску
```

### 5.3 Пошук

Індекс будується в пам'яті під час старту (119 точок + 311 термінів + 71 термін — мілісекунди), без зовнішніх бібліотек.

1. **Нормалізація:** нижній регістр, `ё→е`, прибрати пунктуацію; для кодів — `м→m`, `в→b`, `1/2→½`, прибрати пробіли.
2. **Токенізація** за словами; збіг за **префіксом** токена (R2.7) — стемінг російської не потрібен.
3. **Ранжування:** точний код 100 → початок коду 80 → заголовок 60 → термін покажчика 50 → опис 30 → нотатка 20 →
   термін словника 10 → визначення словника 5. Усі слова запиту обов'язкові, але можуть бути в різних полях;
   оцінка — середнє найкращих ваг по словах, +5, якщо всі слова знайшлись в одному полі.
   За рівної оцінки точки йдуть за природним порядком кодів, симптоми й терміни — за алфавітом;
   серед симптомів коротша назва стоїть вище.
4. **Фрагмент:** ±40 символів навколо першого збігу в полі, де збіг знайдено.
5. Пошук виконується з затримкою 80 мс після останнього символу.

## 6. Обробка крайніх випадків

| Випадок | Поведінка |
|---|---|
| Код у покажчику без описаної точки (`11E`, `25Mправая`, рукописне `15`) | Сірий неактивний бейдж із підказкою «точки з таким кодом у книзі немає» |
| Точка без згадок у покажчику (67, 70, 85) | Блок «Симптоми» на сторінці точки не показується |
| Точка без власного заголовка (X, 94) | Заголовок із транскрипції + примітка транскрипції внизу |
| Посилання на неіснуючий маршрут (веб) | Екран «Не знайдено» з кнопкою «На головну» |
| Пошкоджені збережені дані | Скидання до порожнього стану без падіння |
| Дуже великий системний шрифт | Рядки списків переносяться; бейдж коду не стискається |

## 7. Тестування

- **Модульні:** нормалізація й ранжування пошуку (таблиця запит → очікуваний перший результат), розбір `content.json`,
  обмеження й дедуплікація історії, об'єднання дублікатів симптомів.
- **Перевірка даних (у CI):** кожен `figureId`, `relatedCode`, `symptomId` розв'язується; кожен asset існує.
- **Віджетні:** Головна (порожня та з історією), Точка (звичайна, зі сторонами, без симптомів), порожні стани.
- **Golden:** Головна і Точка у світлій і темній темах.
- **Інтеграційний сценарій:** пошук «голов» → точка → обране → перезапуск → обране та історія на місці.

## 8. Передумови й ризики

- **Flutter SDK не встановлено** на цій машині (є лише `fvm`). Перший крок реалізації — `fvm install stable` і `fvm use`.
- **Якість малюнків:** скани різної контрастності. У MVP показуємо як є на «паперовій» підкладці; вирівнювання контрасту — окреме завдання за бажанням.
- **Точність контенту:** транскрипція ручна, без суцільної вичитки. Сторінка точки показує номер сторінки джерела, щоб можна було звіритись.
- **Сторони публікації:** якщо застосунок піде в стори, медична тематика вимагатиме окремої уваги до опису й застережень.
